# «Перед отправкой» — Implementation Plan

> Для кодинг-агента: выполняй план последовательно, по одному этапу. При наличии навыка superpowers:executing-plans используй его. Отмечай выполненные пункты. Реализацию начинай только по запросу пользователя.

**Цель:** общедоступный браузерный редактор, в котором человек вставляет скриншот, скрывает личные данные, добавляет пояснения и скачивает PNG.

**Архитектура:** одностраничное приложение без сервера. React управляет интерфейсом и состоянием; Canvas 2D рисует изображение, разметку и экспорт. Исходник хранится в памяти отдельно от истории редактирования; предпросмотр и экспорт используют одну функцию рисования.

**Стек:** React, TypeScript со strict mode, Vite, обычный CSS, Vitest, Playwright, npm. Без UI-китов, Redux, библиотек редактирования изображений, внешних шрифтов и платных API. Версии зависимостей выбираются совместимые на момент создания и фиксируются package-lock.json. Node — поддерживаемая LTS-версия, удовлетворяющая требованиям выбранного Vite; её major фиксируется в .nvmrc и workflow.

**Спецификация:** разделы 1–4 этого документа. Это самостоятельный план: для реализации не нужна предыдущая переписка.

**Оценка:** семь вечеров по 2–3 часа плюс возможный резерв на браузерные ошибки. Это оценка, а не гарантия. Если времени не хватает, переносится срок; проверки экспорта и приватности не убираются.

## 1. Что именно строим

Рабочее название репозитория: `beforeshare`. Название в интерфейсе: «Перед отправкой». Интерфейс на русском; README на английском, чтобы проект было проще найти и использовать.

Основной сценарий:

1. Пользователь открывает сайт.
2. Выбирает PNG/JPEG, перетаскивает файл или вставляет изображение через Ctrl+V / Cmd+V.
3. Выделяет прямоугольники чёрной закраски над личными данными.
4. При необходимости обрезает изображение, добавляет стрелки и номера.
5. Нажимает «Скачать PNG» и получает плоское изображение с внесёнными изменениями.

В v1 есть только один открытый скриншот и четыре инструмента: «Скрыть», «Стрелка», «Номер», «Обрезать». Также есть отмена, повтор, показ всей картинки по размеру рабочей области и загрузка другого файла.

В v1 НЕ входят: OCR, ИИ, размытие, пикселизация, свободный текст, рисование кистью, редактирование существующих фигур, поворот, несколько файлов, PDF/SVG/GIF/WebP, история между сессиями, PWA, аккаунты, аналитика, сервер, платные функции и копирование результата в буфер. Никакой функции сверх этого списка до выпуска v1.

## 2. Зафиксированные требования

### Ввод

- Только декодируемые PNG и JPEG: тип проверять по сигнатуре файла, а не только расширению или MIME. APNG отклонять с объяснением, что анимация не поддерживается.
- Максимум 20 MiB на файл, 20 000 000 пикселей и 6000 пикселей по любой стороне. Границы включительно. До декодирования проверять размер файла, после — размеры изображения.
- Если передали несколько файлов, ничего не загружать; показать «Выберите одно изображение».
- При замене открытого изображения спросить «Открыть другое изображение? Текущие изменения будут потеряны». Старое изображение сохранять, пока новое не прошло проверки и не декодировалось.
- Пустой буфер и текстовая вставка не вызывают ошибку. Вставку не перехватывать в input, textarea и contenteditable.
- На время декодирования блокировать повторную загрузку. На время экспорта блокировать изменения документа и повторное скачивание.
- Сообщения ошибок показывать на странице, без падения приложения. Предусмотреть ошибки чтения, повреждённого файла, превышения лимитов, неподдерживаемого формата и экспорта.

### Редактирование

- После загрузки активен инструмент «Скрыть».
- Закраска: непрозрачный чёрный прямоугольник, без скругления, размытия и прозрачности. Рисование перетаскиванием в любом направлении.
- Стрелка: от начала жеста к концу, цвет #F97316, толщина 4 пикселя исходника, белая подложка 7 пикселей, наконечник длиной 16 пикселей. Длина меньше 8 пикселей исходника — отменить жест.
- Номер: один клик ставит оранжевый круг радиусом 16 пикселей с белой обводкой 2 пикселя и белым числом шрифтом bold 18px system-ui. Нумерация 1–99; после 99 показать «Достигнут предел: 99 меток». Следующий номер — максимум существующих номеров плюс один; отмена позволяет использовать отменённый номер снова.
- Обрезка: перетаскивание задаёт прямоугольник внутри текущей видимой области. После отпускания показать «Применить» и «Отмена»; Enter применяет, Escape отменяет. Минимум 16 × 16 пикселей исходника. Обрезка не меняет координаты фигур и исходник, а меняет видимую область документа.
- Закраска меньше 2 × 2 пикселей исходника не добавляется. При сохранении её границы округляются наружу до целых пикселей и ограничиваются границами изображения.
- Порядок рисования: исходник → стрелки и номера в порядке добавления → все чёрные закраски → временный интерфейс активного инструмента. Закраски всегда перекрывают другие фигуры.
- Нельзя двигать и удалять отдельные готовые фигуры. Исправление ошибки — отмена и повторное рисование. Это сознательное ограничение v1.
- История содержит максимум 50 завершённых действий, каждое — снимок небольшого состояния документа. Исходное изображение не копируется в историю. Одна фигура или применённая обрезка — одно действие; движения мыши не создают историю.
- Undo: Ctrl/Cmd+Z. Redo: Ctrl/Cmd+Shift+Z; дополнительно Ctrl+Y на Windows. После новой правки ветка redo удаляется. Нажатия в полях ввода не перехватывать.
- Escape и pointercancel отменяют незавершённый жест без записи в историю. Переключение инструмента также отменяет черновик. Использовать Pointer Events и pointer capture: отпускание за пределами картинки не оставляет интерфейс в состоянии рисования.

### Экспорт и приватность

- PNG строится на новом canvas из пикселей исходника и завершённых фигур. Не включать рамки, подсветку, черновики, служебные ручки, историю или исходный файл.
- Размер PNG равен размеру применённой обрезки в пикселях исходника; без обрезки — исходному размеру. Не умножать размер экспорта на devicePixelRatio.
- Чёрные области экспорта имеют RGB 0,0,0 и alpha 255 на всей площади прямоугольника, включая края. Использовать integer fillRect при сброшенных тенях и globalAlpha=1.
- В экспорт не переносить исходные EXIF/текстовые метаданные и имя исходника. Имя скачивания: `beforeshare-YYYYMMDD-HHmmss.png` по локальному времени пользователя.
- Удалять временные object URL после использования; освобождать bitmap при замене/сбросе. Не хранить изображения в localStorage, IndexedDB или логах.
- Никаких запросов с изображением или его содержимым. Зависимости и ресурсы включить в сборку; никаких CDN, удалённых шрифтов, аналитики и telemetry SDK.
- Текст на странице: «Изображение обрабатывается в вашем браузере и не отправляется на сервер». Не обещать автоматическое обнаружение всех личных данных. Пользователь сам выбирает области.
- Безопасность итогового PNG не означает, что незакрытые участки или оригинал на компьютере перестают существовать.

### Интерфейс

- Светлая тема, фон #F8FAFC, белые панели, основной текст #0F172A, акцент #F97316, системный шрифт. Скругление панелей 12px, отступы кратны 8px. Без анимаций и декоративной графики.
- До загрузки: название, фраза «Вставь скриншот. Скрой лишнее. Отправь.», зона загрузки, кнопка «Выбрать изображение», подпись «PNG или JPEG · до 20 MiB · до 20 Мп · до 6000 px по стороне», сообщение о локальной обработке.
- После загрузки: верхняя панель с названием и кнопкой «Открыть другое», ниже инструменты и undo/redo, рабочая область на шахматном фоне, под ней размер результата и «Скачать PNG».
- Картинка вписывается в ширину и высоту доступной области; не увеличивается выше 100% CSS-масштаба. Изменение размера окна пересчитывает предпросмотр, но не документ.
- Видимый масштаб показывается в процентах. Ручного зума и панорамирования в v1 нет.
- Ориентир — десктоп с шириной от 1024px. На узком экране панели переносятся, загрузка/скачивание доступны, рисование поддерживает touch одним указателем; второй указатель игнорируется. Интерфейс должен помещаться при ширине 360px.
- Все кнопки имеют понятные названия, focus-visible, disabled-состояния. Активный инструмент имеет aria-pressed. Ошибки объявляются через role=alert. Не заявлять полную доступность редактирования без мыши: клавиатурное рисование не входит в v1.

Не создавать дополнительные архитектурные слои без причины. Конфигурационные файлы Vite/TypeScript/ESLint/Playwright/Vitest и точка входа создаются при настройке проекта.

Контракты в TypeScript:

```ts
type Point = { x: number; y: number };
type Rect = { x: number; y: number; width: number; height: number };
type Tool = 'redact' | 'arrow' | 'number' | 'crop';
type Annotation =
  | { id: string; kind: 'redact'; rect: Rect }
  | { id: string; kind: 'arrow'; from: Point; to: Point }
  | { id: string; kind: 'number'; at: Point; value: number };
type EditorDocument = { crop: Rect; annotations: Annotation[] };
type LoadedImage = { bitmap: ImageBitmap; width: number; height: number };
type HistoryState = {
  past: EditorDocument[];
  present: EditorDocument;
  future: EditorDocument[];
};

loadImage(file: File): Promise<LoadedImage>;
normalizeRect(a: Point, b: Point, bounds: Rect): Rect;
clientToImage(client: Point, canvasRect: Rect, crop: Rect): Point;
appendAnnotation(doc: EditorDocument, item: Annotation): EditorDocument;
applyCrop(doc: EditorDocument, rect: Rect): EditorDocument;
commit(history: HistoryState, next: EditorDocument): HistoryState;
undo(history: HistoryState): HistoryState;
redo(history: HistoryState): HistoryState;
renderScene(ctx: CanvasRenderingContext2D, image: LoadedImage,
            doc: EditorDocument, scale: number): void;
exportPng(image: LoadedImage, doc: EditorDocument): Promise<Blob>;
downloadBlob(blob: Blob, filename: string): void;
```

`EditorDocument.crop` всегда в целых координатах исходника. Начальное значение — весь исходник. Все фигуры тоже хранятся в координатах исходника. Preview задаёт backing canvas с учётом devicePixelRatio, затем передаёт renderScene масштаб backing canvas / crop. Экспорт передаёт scale=1. renderScene очищает canvas, задаёт преобразование и смещение относительно crop, обрезает рисование по crop. Черновик рисуется отдельно только в preview.

Преобразование указателя: `x = crop.x + (client.x - canvasRect.x) * crop.width / canvasRect.width`, аналогично y. canvasRect — видимый DOM-прямоугольник без border/padding. Полученную точку ограничить crop. Canvas обернуть отдельным элементом для рамки.

## 4. На что обратить особое внимание при проверке

1. Скриншот уменьшен на экране: фигуры и обрезка должны совпадать с экспортом. Проверяется в этапах 2 и 5.
2. Прозрачный PNG: закраска должна оставаться непрозрачной; незакрашенная прозрачность сохраняется. Проверяется в этапе 5.
3. JPEG с EXIF-ориентацией: изображение показывается правильной стороной, размер и экспорт соответствуют декодированному изображению. Проверяется в этапах 1 и 5.
4. Жест закончился вне canvas или был отменён системой: нет залипшей фигуры и лишней записи undo. Проверяется в этапах 3 и 6.
5. Новый файл повреждён или слишком большой: текущая работа не теряется. Проверяется в этапах 1 и 6.

## 5. Правила работы кодинг-агента

- Не реализовывать весь проект одним проходом. Один этап → проверки → отчёт → следующий этап по команде пользователя.
- Внутри этапа сначала писать целевые тесты для логики/ошибок, проверять ожидаемый провал, затем делать реализацию. Не писать тесты ради проверки текста кнопок или CSS.
- После каждого этапа запускать `npm run lint`, `npm run typecheck`, `npm run test:unit`, `npm run build`, а также e2e, когда они появились. Ошибки исправлять до следующего этапа.
- Вести `PROGRESS.md`: завершённые пункты, команды и результаты, известные проблемы, следующий этап. Записывать только реально выполненные проверки; отсутствие запуска отмечать явно.
- Делать один локальный git commit на законченный этап, если репозиторий доступен. Не менять чужие незакоммиченные файлы без необходимости.
- При сбое сначала воспроизвести и локализовать причину; не переписывать приложение целиком.
- Не менять стек, лимиты и объём v1. Небольшие решения внутри требований принимать самостоятельно. Внешние блокеры доступа сообщать точно.
